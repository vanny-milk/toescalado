# Planning Policy

This document establishes the mandatory planning process before executing major code changes in the ToEscalado application.

## 1. Think Before You Code
- Never jump straight into writing or modifying code when dealing with complex tasks, architectural changes, or new feature implementations.
- Always analyze the current project state, read relevant existing files, and understand dependencies first.

## 2. Research Phase
- Use directory listings and file-reading tools to understand the context.
- Check for existing Knowledge Items (KIs), previous conversation logs, or implemented patterns that solve similar problems.

## 3. Implementation Plan Creation
- When creating an implementation plan, clearly define:
  - The Goal Description.
  - Any User Review Required / Open Questions.
  - Proposed Changes (categorized by new, modified, or deleted files).
  - A Verification Plan (how to test the changes).
- Wait for explicit user approval on the plan before starting the execution.

## 4. Exceptions
- Simple tasks (e.g., "fix this typo", "change this color", "run this command") do not require a formal implementation plan. Common sense should dictate when a task is simple enough to bypass the planning mode.
